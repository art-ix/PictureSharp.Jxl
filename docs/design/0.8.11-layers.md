# Layer API for 0.8.11

Status: implemented (2026-11-02), released as 0.8.11. Base: `07e82ae` (0.8.10).

0.8.11 is the second step of the feature series (roadmap in plan.md: 0.8.10 blending and flattened layers, 0.8.11
plugin layer API, 0.8.12 animation decode, 0.8.13 animation encode, 0.8.14 noise and splines, 0.8.15 extra channels,
0.8.16 hardening, 0.9.0). The core has no layer model (user decision 2026-11-01: costly, and only JPEG XL would use
it), so the API lives in the plugin, in `PictureSharp.Formats.Jxl`, and is built from the public `Image` type.

Goal: read the layers of a layered JPEG XL still image as separate images, each with its position, name and blend
mode, plus the flattened image exactly as `Image.Load` returns it. Read only; writing layers is not planned before
0.9.0. `Image.Load` and every existing result stay unchanged.

## What exists

- 0.8.10 decodes layered stills: `Frames/JxlDecodeSession.Decode` renders every displayed frame in the image's
  original encoding (`JxlFrameDecoder.RenderColor`, frame-sized float planes, the frame's own `JxlBufferScope`),
  blends it onto its background slot (`Rendering/JxlBlending.BlendFrame`) and stores the canvas in its slot. A last
  frame that needs no blending keeps the 0.8.9 path (`JxlFrameDecoder.Finish`, integer samples, deferred YCbCr rows).
- `JxlFrameHeader` has everything a layer description needs: `Type`, `X0`/`Y0` (negative allowed), `Width`/`Height`
  and `Upsampling`, `Blending` and `ExtraChannelBlending` (mode, source, alpha channel, clamp), `SaveAsReference`,
  `SaveBeforeColorTransform`, `IsLast` and `Name`. `JxlDecodeSession.ReadFrameHeaders` reads all frame headers and
  TOCs without decoding.
- Output: `Integration/JxlPixelWriter.Write`/`WriteWide` turn a `JxlDecodedImage` (planes + alpha + encoding) into an
  `Image`, with the dither pattern flipped for the stored orientation when `ApplyExifOrientation` is set
  (`DitherFlip`). `JxlMetadataReader` applies colour, EXIF/XMP and orientation.
- Core facts that shape the design (PictureSharp 0.9.0):
  - `ImageDecodeContext` (with `ReservePixels`, `ReserveMetadata`, the cancellation token) has no public
    constructor; a plugin gets one only inside `IImageFormatDecoder.Decode`, called by the core's `Image.Load`.
  - After the decoder returns, `Image.Load` converts to sRGB (`ColorConversion = ToSrgb`, decoding at 16 bits and
    reducing to 8 when `PreserveBitDepth` is off), applies `TargetSize`, then `AutoOrient` when
    `ApplyExifOrientation` is set (default false), and wraps corrupt-data exceptions.
  - `ReservePixels(width, height, type, frames)` accumulates over one load: `MaxPixels` (Rgba64 counts twice) and
    `MaxFrames` are totals, and the core checks that the returned image was reserved.
  - Public processing: `AutoOrient()`, `ConvertToSrgb()`, `ConvertPixelType(...)`.

## What libjxl does (v0.12.0)

- `JxlDecoderSetCoalescing(dec, false)` (`djxl --no_coalescing --output_frames`): every regular frame (not
  reference-only, not DC, not skip-progressive patches-only) is returned as its own image of the frame's upsampled
  size, not blended. `JxlDecoderGetFrameHeader` reports `layer_info`: `crop_x0/y0` (signed), `xsize/ysize`,
  `blend_info` (mode, source, alpha, clamp), `save_as_reference`, and the name; per extra channel
  `JxlDecoderGetExtraChannelBlendInfo`.
- Pixels are in the output colour encoding (the original one unless XYB is rendered to a requested space), with the
  frame's own alpha; nothing outside the frame is produced.
- Orientation (`GetCurrentDimensions`, `JxlDecoderGetFrameHeader`): unless `keep_orientation` is set (it is not by
  default), each layer is oriented and its crop offset is mapped into the oriented canvas: for orientations > 4 swap
  x0/y0, then `x0 = W − xsize − x0` for flips in x and `y0 = H − ysize − y0` for flips in y.
- libjxl's encoder writes layers as a stack: `FrameInfo.source = 1` and every non-last frame
  `save_as_reference = 1` (jxl_from_tree, `JxlEncoderSetFrameHeader` users such as GIMP/Krita export with the same
  defaults); extra channels other than alpha default to `Add` (enc_frame.cc).
- With coalescing (the default, = `Image.Load`) the layers are blended into one canvas as 0.8.10 does.

## Design

### Public types (`PictureSharp.Formats.Jxl`)

```csharp
public static class JxlLayers
{
    public static JxlLayeredImage Load(string path, DecoderOptions? options = null, CancellationToken cancellationToken = default);
    public static JxlLayeredImage Load(Stream stream, DecoderOptions? options = null, CancellationToken cancellationToken = default);
    public static JxlLayeredImage Load(ReadOnlyMemory<byte> data, DecoderOptions? options = null, CancellationToken cancellationToken = default);
    public static Task<JxlLayeredImage> LoadAsync(string path, DecoderOptions? options = null, CancellationToken cancellationToken = default);
    public static Task<JxlLayeredImage> LoadAsync(Stream stream, DecoderOptions? options = null, CancellationToken cancellationToken = default);
    public static JxlLayeredImageInfo Identify(string path, DecoderOptions? options = null);
    public static JxlLayeredImageInfo Identify(Stream stream, DecoderOptions? options = null);
    public static JxlLayeredImageInfo Identify(ReadOnlyMemory<byte> data, DecoderOptions? options = null);
}

public sealed class JxlLayeredImage : IDisposable
{
    public int Width { get; }                       // canvas (oriented when ApplyExifOrientation)
    public int Height { get; }
    public IReadOnlyList<JxlLayer> Layers { get; }  // bottom (first frame) to top (last frame)
    public ImageMetadata Metadata { get; }          // ICC/colour, EXIF, XMP, orientation: as Image.Load's result
    public Image Flatten();                         // a new Image equal to Image.Load(data, options); caller owns it
    public void Dispose();                          // disposes the layer images and the flattened canvas
}

public sealed class JxlLayer
{
    public Image Image { get; }                     // the layer's own size; owned by the JxlLayeredImage
    public Point Offset { get; }                    // on the canvas; may be negative or outside it
    public string Name { get; }                     // frame name, "" when unnamed
    public JxlLayerBlendMode BlendMode { get; }
    public bool Clamp { get; }                      // blended values clamped to [0, 1]
}

public enum JxlLayerBlendMode { Replace, Add, Blend, AlphaWeightedAdd, Multiply }

public sealed record JxlLayeredImageInfo(ImageInfo Image, IReadOnlyList<JxlLayerInfo> Layers);
public sealed record JxlLayerInfo(string Name, Point Offset, Size Size, JxlLayerBlendMode BlendMode, bool Clamp);
```

`Point`/`Size` are `System.Drawing` like `Image.Size`/`Bounds`. `JxlLayer` has no public constructor and is not
disposable on its own. `Image` of a layer carries the colour description (ICC profile or enumerated colour) so that it
can be converted on its own; EXIF and XMP are only on `JxlLayeredImage.Metadata`. `JxlLayerInfo.Size` is the
upsampled frame size, i.e. `JxlLayer.Image.Size` before orientation.

Blend modes map one to one to the frame header (`Mul` → `Multiply`); `Blend` and `AlphaWeightedAdd` use the image's
alpha channel (see the stack rules). A user who composites the layers with these modes in float over a transparent
black canvas gets `Flatten()` up to rounding; `Flatten()` itself is the exact result.

### One decode through the core

`JxlLayers.Load` runs `Image.Load` (path, stream or memory overload) with the caller's options and a per-call
configuration in which the JPEG XL module is replaced by an internal layer module (`Integration/JxlLayerModule`,
same format, same `Identify`, its own decoder); the configuration keeps only that module, so other formats are
rejected as unknown. Its decoder runs one `JxlDecodeSession` that reports each layer and
returns the flattened canvas as the image of that load. So:

- the input limits, stream and file handling, cancellation and error wrapping are those of `Image.Load`;
- every layer is charged with `ImageDecodeContext.ReservePixels` before it is allocated, as the brief asks, and the
  core checks the totals: `MaxPixels` covers canvas + all layers, `MaxFrames` counts the canvas and each layer
  (N + 1), and the session still counts codestream frames against `MaxFrames` as `Image.Load` does;
- the core then post-processes the canvas exactly as for `Image.Load` (ToSrgb, orientation), so `Flatten()` is
  bit-identical by construction and nothing is decoded twice. The plugin applies the same post-processing to each
  layer image itself with the public operations (below).

`Identify` does the same through `Image.Identify` (which has no cancellation token, so neither has `Identify`): the layer module's `Identify` reads the frame headers
(`ReadFrameHeaders`, no pixel decode), applies the stack rules and returns `JxlLayeredImageInfo` with the normal
`ImageInfo` of the image.

Options:

- `PreserveBitDepth`, `IgnoreMetadata`, `MaxDegreeOfParallelism`, `MaxPixels`, `MaxFrames`, `MaxInputBytes`,
  `MaxMetadataBytes`: as for `Image.Load`; layers use the canvas pixel type (Rgba32, or Rgba64 for > 8-bit sources
  with `PreserveBitDepth`).
- `ColorConversion = ToSrgb`: XYB layers are rendered to sRGB in float by the plugin (`JxlCanvasToSrgb`, as the
  canvas in 0.8.10); other layers are converted with the public `ConvertToSrgb()` and, when the caller did not ask for
  `PreserveBitDepth`, reduced to Rgba32 like the core does for the canvas.
- `ApplyExifOrientation`: open decision 1.
- `TargetSize`: rejected with `ArgumentException` (resampling layers and offsets has no exact meaning).
- `FirstFrameOnly`, `LoadGainMap`: no effect (still images; JPEG XL has no gain map in this plugin).

### Which files have layers (the stack rules)

A layer is a `Regular` or `SkipProgressive` frame that is displayed in the coalesced result. Reference-only, DC and
patch-source frames (saved before the colour transform) are not layers. Layers are exposed only when the file is a
simple stack, checked on the frame headers before any pixel is decoded:

1. Not an animation (animations are 0.8.12; `JxlLayers` rejects them then too).
2. Each layer after the first takes its background from the slot the previous layer was saved to
   (`Blending.Source == previous.SaveAsReference`), and no frame between them overwrote that slot.
3. The first layer's background slot is empty (transparent black), or the first layer is a full-size `Replace`.
4. No layer is saved before the colour transform (its blended result would be dropped, as libjxl does).
5. Every extra channel uses the same source slot as the colour; the alpha channel uses the same mode and clamp as the
   colour; `Blend`/`AlphaWeightedAdd` refer to the image's (first) alpha channel. Other extra channels may use other
   modes (libjxl's encoder uses `Add` for them); they are not part of the output in 0.8.11 (0.8.15).

Anything else throws `NotSupportedException("… is not a simple layer stack; use Image.Load for the flattened
image.")` from `Load` and `Identify`. A single-frame image is a stack of one layer (offset 0, `Replace`). Features
that `Image.Load` rejects (noise, splines, spot colours, float) are rejected the same way.

### Decode loop

`JxlDecodeSession` gets an optional layer sink (internal callback). With a sink:

- before a layer is decoded, the sink reserves its pixels (`ReservePixels`, upsampled frame size);
- after `RenderColor` and before blending, the sink receives the frame-sized planes, still inside the frame's
  `JxlBufferScope`, and writes them through `JxlPixelWriter` to the layer `Image` (with `ToSrgb` for XYB through
  `JxlCanvasToSrgb` on a copy). Then blending continues unchanged;
- the last frame on the 0.8.9 fast path (full `Replace`) is written once as the canvas; the layer is a clone of that
  `Image` before the core post-processes the canvas, so both come from the same samples.

Without a sink (all `Image.Load` calls) the loop is the 0.8.10 code; golden results must stay identical.

Layer images are written in parallel row bands like the canvas; results do not depend on the degree. On any failure
or cancellation all layer images written so far are disposed.

### Orientation

See open decision 1. With orientation applied, each layer goes through `AutoOrient()` (its `Metadata.Orientation` set
to the stored one first, reset afterwards), offsets are mapped like libjxl, `Width`/`Height` are swapped for
orientations > 4 and `Metadata.Orientation` is `TopLeft` (as the core leaves it). The writer uses the same
`DitherFlip` for layers as for the canvas.

## Tests and corpus

- `Flatten()` bit-identical to `Image.Load` (default options, `PreserveBitDepth`, `ToSrgb`, `ApplyExifOrientation`)
  on all `tests/assets/corpus/layers-*.jxl`, the single-frame corpus and the conformance files `blendmodes`,
  `mul_no_extra_channels`, `sunset_logo` (ignored corpus; skip when missing).
- Layers against `djxl --no_coalescing --output_frames` (PAM per layer, `-N` suffix; Category=Oracle, skip without
  djxl): sizes, lossless exact, lossy within 1/255, alpha exact; offsets, names, modes against the frame headers
  (jxlinfo does not print blend info, so the expectations for the corpus files are fixed in the test).
- New corpus files from `jxl_from_tree` (slot 1 stack): named layers, an oriented layered file (orientation 6 and 3),
  a non-stack file (two layers blending from an empty slot 0 and slot 1) and one where a reference-only frame
  overwrites the stack slot; the generator gets these cases in `generate-corpus.py`. Alpha layers and VarDCT layers
  come from the conformance files and the internal multi-frame test writer of 0.8.10.
- Rejections: animation, non-stack files, `TargetSize`, frames saved before the colour transform.
- Budgets: `MaxPixels` just below canvas + layers fails before allocation, just at it succeeds; `MaxFrames` = N
  fails, N + 1 succeeds; cancellation before and during a layer; failure after some layers leaves no undisposed image
  (counting pool in the checked build).
- Public API snapshot updated and reviewed; README "Support", `docs/decoding.md`, release notes.
- Golden: unchanged for the existing 1636 results at 1 and 16 threads (the layer sink is off for `Image.Load`).
- Fuzzing: a `layers` target (load + flatten + dispose on the fuzz seeds) in a short run on the PC; long runs in
  0.8.16.

## Results (2026-11-02)

- Code: public `JxlLayers`, `JxlLayeredImage`, `JxlLayer`, `JxlLayerBlendMode`, `JxlLayeredImageInfo`,
  `JxlLayerInfo`; internal `Codestream/Frames/JxlLayerStack` (the stack rules), `Integration/JxlLayerModule` and
  `JxlLayerCollector`, a layer sink in `JxlDecodeSession` (regular and skip-progressive frames only) and

## Open decisions (user)

None open. Decided (user, 2026-11-02), each the recommended option:

1. Orientation follows `ApplyExifOrientation` like `Image.Load`: off (the default) keeps stored layers and offsets
   with `Metadata.Orientation` for the caller; on orients every layer and maps offsets as libjxl does.
2. One decode through the core: the canvas is kept and `Flatten()` returns a copy; layers are charged through
   `ReservePixels`.
3. Names as above (`JxlLayers`, `JxlLayeredImage`, `JxlLayer`, `JxlLayerBlendMode` with `Multiply`,
   `JxlLayeredImageInfo`, `JxlLayerInfo`, `Offset` as `System.Drawing.Point`), with `LoadAsync` for path and stream,
   no `IdentifyAsync`.
4. Extra channels other than alpha may use another mode than the colour; only their source slot must match.
