# Memory ownership in 0.7.10

The public API is unchanged. The codec uses explicit scopes for pooled working storage and retains the same
sample arithmetic, compression decisions and section ordering as 0.7.9. The
[measurements](../benchmarks/speed.md#allocations-and-memory-0710) distinguish allocated bytes, GC counts
and process peak RSS.

## Buffer ownership

`JxlPooledBuffer<T>` owns one ArrayPool rental and returns it once. Its logical length is separate from rented
capacity; its memory/span views cover the requested length. `JxlBufferScope` holds leases and other disposable
resources for a call or a shorter phase. Scope and lease disposal are idempotent, allowing an early return of
storage already registered with a surrounding scope.

Existing array-based kernels keep their signatures. Rows, token views and codestream segments use exact slices;
channel loops use width × height rather than the bucket length. Zero-initialized working state is cleared over
its requested region before use. Fully overwritten token, sample and writer storage does not need an initial
clear. Growth copies valid elements and returns superseded token/sample/writer rentals promptly.

| Lifetime | Storage | Release point |
| --- | --- | --- |
| Decode call | Full-image integer channels, VarDCT planes and live references | After writing PictureSharp-owned pixels, or on failure |
| Modular group | Channel crops and transform storage | After copying restored group samples into full-image channels |
| VarDCT LF group | Integer DC and AC metadata channels | After scattering values into frame state |
| VarDCT AC group | Coefficients accumulated over every pass | After group rendering or JPEG coefficient recovery |
| Kernel/channel | DCT blocks, nonzero tables, predictor and reference rows | At the end of that kernel/channel, including exceptions |
| Encoder working phase | XYB planes, coefficients, token streams and tree samples | At their last explicit consumer or at working-scope disposal |
| Encoder output | Prepared header and section bytes | After destination writing succeeds, is cancelled or fails |

The decoder adapter keeps its call scope alive through pixel writing. `JxlDecodedImage` borrows its samples;
the returned PictureSharp image owns independent pixels. Transform-created channels inherit the appropriate
scope, so removing a channel from an image list does not lose its cleanup registration. Internal callers that
omit a scope retain GC-owned storage.

The encoder separates working storage from retained output sections. Initial XYB and EPF reference copies can
return early after their final consumers; the remaining working scope is disposed before destination I/O.
Tree samples use an inline append path with growth isolated in a cold method. Encoder token collections and
stream sets own their rentals, including partially prepared work when an operation fails.

## Section assembly

A segmented `JxlBitWriter` records prepared header and section memories. Integration owns their output scope
and exposes a borrowed IO `JxlCodestream` view to the container writer. Section sizes are known before the TOC
and length-bearing jxlc header are written, so output works with non-seekable streams without backpatching.
No full codestream-sized intermediate array is required for image encoding.

Multi-group sections retain their individual byte padding. A single-group frame still combines subsection
bits into one section and pads only once. Empty TOC entries and patch reference frames retain their positions.
Input jxlc/jxlp payloads already use borrowed slices and are not flattened by the container parser. JPEG
transcoding retains its existing public buffering boundary while sharing token and predictor improvements.

## Integer output

Common finalization consumes frame progress, reverses Modular transforms and validates channel counts and
shapes before selecting the result representation. The direct integer result requires a regular, full-frame
Modular image with non-XYB integer samples through 16 bits, no colour transform, no Gaborish/EPF, no patches
and no frame or extra-channel upsampling. Other supported cases retain the float rendering pipeline.

The pixel writer checks the integer representation before accessing rendered planes. It preserves the old
float reciprocal and sample multiplication, followed by the existing 8-bit dither or 16-bit clamp/round formula.
There is no intermediate float plane or row. Gray uses dither channel 0 and alpha 1; RGB uses 0/1/2 and alpha 3.
Wide output has separate gray/RGB and alpha/opaque loops, with image construction outside the hot row method.

## Histogram and colour work

FindSplit initializes only storage needed for the current node and predictor. Sparse predictors reset active
bin/symbol cells; dense predictors use Span.Clear over the active bin interval. Every cell read or incremented
is initialized even when the symbol stride changes between nodes. Traversal order, cost sums and tie-breaking
are unchanged.

XYB-to-sRGB output dispatches the transfer function outside the pixel loop and shares the original XYB-to-linear
arithmetic with the generic path. ICC and other transfers keep their existing conversion paths. No new transfer
approximation, lookup table, SIMD or parallelism is introduced.

## Verification and limits

Release verification covers 474 tests, a 1283-result byte/pixel/metadata/exception comparison against the 0.7.9
package, and the actual nupkg under JIT, full trimming and linux-x64 Native AOT. Added cases cover oversized dirty
rentals, idempotent return, unaligned section concatenation, every sample at depths 1–16, non-seekable output,
destination failure and immediate reuse after failure.

Warm allocation reductions are not cold-allocation or peak-RSS guarantees. Pool bucket rounding and retained
storage can increase process peak RSS in individual cases. Output reservations still account for output pixels
and metadata; they do not impose a new budget on all temporary codec storage.
