# Frame blending and flattened layers for 0.8.10

Status: implemented (2026-11-02), not committed. Base: 0.8.9.

0.8.10 is the first step of the feature series (roadmap in plan.md, user decision 2026-11-01): 0.8.10 blending and
flattened layers, 0.8.11 plugin layer API, 0.8.12 animation decode, 0.8.13 animation encode, 0.8.14 noise and
splines, 0.8.15 extra channels, 0.8.16 the hardening formerly planned for 0.8.10, then 0.9.0. Blending is the
foundation of the next three steps: layers are frames blended onto a canvas, and an animation frame is the canvas
after blending.

Goal: a still image made of several displayed frames decodes through `Image.Load` to one canvas, exactly as
`djxl` does with its default `coalescing = true`. No public API change. Animations still throw
`NotSupportedException` (0.8.12).

## What exists

- `Frames/JxlDecodeSupportPolicy.EnsureFrameSupported` rejects a `Regular` frame that is not last, every
  `SkipProgressive` frame and every regular frame that is cropped (`X0`/`Y0`/size ≠ image) or does not use Replace for
  colour and every extra channel.
- `Frames/JxlDecodeSession.Decode` decodes reference-only and DC frames into `JxlReferenceFrames`, then returns the
  first regular frame (`JxlFrameDecoder.Finish`). A reference-only frame saved after the colour transform is skipped,
  and `Buffers/JxlReferenceFrames.StoreReference` refuses to store one.
- `JxlReferenceFrame` holds GC-owned colour and extra planes; patches read them (`Rendering/JxlPatches.Apply`).
- `Rendering/JxlPatches.Blend` already ports libjxl's per-pixel `PerformBlending` (all `PatchBlendMode`s, extra channels
  first with the alpha before blending, `alpha.cc` alpha blending, clamp). Frame blending uses the same operations.
- `JxlFrameHeader` already parses `Blending`, `ExtraChannelBlending` (mode, source slot, alpha channel, clamp),
  `X0`/`Y0`/`Width`/`Height`, `Duration`, `SaveAsReference`, `SaveBeforeColorTransform` and `Name`. The frame
  decoder and renderer size everything by `frame.Width`/`Height`, but have never seen a cropped frame.
- Fast paths that must stay: `JxlFrameDecoder.Finish` returns integer samples for plain lossless frames, and the
  YCbCr rows are rendered on demand by the consumer (`JxlYCbCrRows`, 0.8.6).

## What libjxl does (v0.12.0)

- `NeedsBlending` (blending.cc): a regular or skip-progressive frame needs blending unless it covers the image
  (`custom_size_or_origin` false) and every mode is Replace.
- `CanBeReferenced` (frame_header.h): not last, not a DC frame, and either `duration == 0` or `save_as_reference != 0`.
  In a still image every frame before the last has duration 0, so each one is saved to its slot.
- Pipeline order (dec_cache.cc `PreparePipeline`): … patches, splines, upsampling, noise; the frame is saved here if
  `save_before_color_transform`; then YCbCr or XYB to the output encoding; if the frame needs blending, convert from
  linear and run `BlendingStage`; if it can be referenced and is saved after the colour transform, save the blended
  result; then spot colours, tone mapping, CMS, output.
- `BlendingStage` (stage_blending.cc): background = the colour slot `blending_info.source`, and for each extra
  channel its own `source`; an empty slot is zeros; a background smaller than the image or with an origin is an error;
  an XYB-saved slot (`ib_is_in_xyb`) cannot be a blending background; for XYB images blending requires the output
  encoding to be the original one. Pixels outside the frame copy the background (`ProcessPaddingRow`); the frame is
  clipped to the image, offsets may be negative. Modes map Blend → BlendAbove, AlphaWeightedAdd →
  AlphaWeightedAddAbove.
- `FinalizeFrame` (dec_frame.cc) moves the saved image into `reference_frames[save_as_reference]` with its
  `ib_is_in_xyb` flag.

## Design

### Decode loop

`JxlDecodeSession.Decode` keeps one loop over frames, now with three outcomes per frame:

1. DC frame → `StoreDc` (unchanged).
2. Saved before the colour transform (reference-only or not) → `Store()` as today, slot marked "before CT".
3. Regular or skip-progressive frame → render with the colour transform; if `NeedsBlending`, blend onto the
   background slot into a new full-size canvas; if `CanBeReferenced` and saved after the colour transform, store the
   canvas in its slot marked "after CT"; if `IsLast`, the canvas is the image. A reference-only frame saved after the
   colour transform is rendered and stored the same way (it is no longer skipped).

A regular frame that is neither last nor referenceable is decoded for its side effects only (none in a still image)
and dropped, as libjxl does. Frames that are not displayed still count against `MaxFrames`.

### Fast path

When the last frame does not need blending and no earlier frame was decoded, the session takes exactly today's
path: integer samples, deferred YCbCr rows, no extra canvas. Golden results (1542) must stay identical at 1 and 16
threads; this is the main acceptance gate for the refactoring.

### Canvas and slots

- Canvas (as implemented): a `JxlReferenceFrame` of GC-owned, full-size float planes (3 colour + every extra channel)
  in the image's encoding, charged to `JxlWorkBudget` when allocated. A slot keeps a reference to the canvas that was
  stored; the next frame writes a new canvas (no in-place blending into a slot that is still referenced), so a canvas
  no slot refers to any more is collected. Each blended frame is decoded with its own `JxlBufferScope`, disposed after
  blending; `JxlWorkBudget.Rewind` then sets the charge back to what it was before the frame plus the distinct planes
  still held (`JxlReferenceFrames.RetainedBytes`). Frames saved before the colour transform keep today's decode-wide
  scope and charges.
- `JxlReferenceFrames` stores the frame and whether it was saved before the colour transform. `GetPatch` is unchanged;
  `GetBackground(slot, width, height)` returns null for an empty slot and throws Corrupt for a before-CT slot or one
  not of the image size, as `BlendingStage` does.
- Gray images: canvases always have three colour planes (libjxl's Image3F); a gray frame rendered as one plane is
  read as three, and a copied gray frame shares one plane three times.

### Blending

- New `Rendering/JxlBlending`: libjxl's per-pixel `PerformBlending` moved out of `JxlPatches` unchanged, so that
  patches and frames share one implementation, plus `BlendFrame` (BlendingStage) and `NeedsBlending`. Port remains
  attributed to blending.cc/alpha.cc/stage_blending.cc. Blend and AlphaWeightedAdd with an alpha channel index outside
  the extra channels are Corrupt.
- Frame placement: rows of the frame clipped to the image (negative `X0`/`Y0`, frames larger than the image or wholly
  outside); rows and columns not covered copy the background or zeros.
- Parallel in row bands through `JxlParallel` (blending is per pixel, so results do not depend on the degree).
  Scalar first; a `JxlBlending.Simd.cs` only with a measured gain.

### Colour encoding

Blending happens in the image's original encoding (`JxlColorTarget.Profile`), like libjxl: XYB frames are rendered
from linear to the original transfer function before blending, non-XYB frames are already there. Two consequences:

- `ColorConversion = ToSrgb` (`renderSrgb`): today XYB frames go straight to sRGB. For images that need blending the
  canvas is blended in the original encoding and converted to sRGB afterwards. Decided (user, 2026-11-02): the plugin
  converts the float canvas when the original encoding is enumerated or a matrix/TRC profile (`JxlIccTarget` curves),
  so 8-bit output is quantized once; otherwise the original pixels and profile go to the core as for non-XYB images.
- The integer-sample path is not used for blended images; lossless frames reach the output through the float writer.
  Replace-only crops of lossless images must still match djxl exactly; other modes produce float results and must
  match within the lossy tolerance (djxl also rounds from float).

### Support policy

`EnsureFrameSupported` keeps: animation (image-level, 0.8.12), noise and splines (0.8.14), the Corrupt checks. It
removes: not-last regular frames, skip-progressive frames, crops and non-Replace modes. New Corrupt cases from
`BlendingStage`: background slot saved before the colour transform, cropped background, alpha channel index outside
the extra channels for Blend/AlphaWeightedAdd.

### Limits and memory

The output is charged as today (`ReservePixels` once). Working memory per decode grows by the canvas
(`(3 + extra) × 4` bytes per pixel) and up to four stored canvases; all are charged to the internal working budget
(`K × MaxPixels`, 0.8.9) before allocation. A file that stores four full canvases is a legitimate input, so K must
cover it; the `limits` measurement in 0.8.16 confirms K with layered inputs. Cancellation is checked per row band
as in the other stages.

## Tests and corpus

- Generator: `jxl_from_tree` built from the pinned libjxl 0.12.0 sources (dev tool, not shipped; build in
  `~/.cache/picturesharp-jxl/libjxl-0.12.0-build`, GCC 13 with the system highway/brotli/lcms2, linked from
  `~/.local/bin`). It writes Modular frames with `FramePos` (negative too), `NotLast` and `BlendMode`; every frame but
  the last is saved to slot 1. It cannot combine several frames with `Alpha` (fails), so alpha blending, other slots
  and VarDCT layers come from our own encoder through an internal test-only multi-frame writer (frame headers with
  origin, blend info and `SaveAsReference`).
- Conformance corpus: libjxl/conformance `b1d0f99` (2026-09-06) cloned into the ignored `tests/assets/external/
  conformance` (44 MB, never committed). 0.8.10 targets `blendmodes` (5 full-size layers, 12-bit, alpha),
  `mul_no_extra_channels` (Mul) and `sunset_logo` (2048×1024 layers at (−662, −100) on a 1386×924 image). Later steps:
  animations 0.8.12, `noise`/`animation_spline` 0.8.14, `spot`/`alpha_premultiplied` 0.8.15; `cmyk_layers` and
  `lossless_pfm` stay unsupported. Each case has `test.json` (rms/peak error per frame) and `ref.png`, some a
  `reference_image.npy`; tests skip when the directory is missing.
- Cases: each blend mode × alpha present/absent × premultiplied (rejected until 0.8.15) × clamp; crops with
  negative and out-of-image origins, 1×1 frames, frames larger than the image; empty background slot; slots 0–3;
  blending from a slot saved before the colour transform (Corrupt); XYB lossy layers; gray; 16-bit; patches from a
  slot saved after the colour transform; `SkipProgressive`; `MaxFrames`.
- Oracle: `djxl` default (coalesced) output compared with `Image.Load` (lossless exact for Replace crops, otherwise
  within 1/255), also with `ColorConversion = ToSrgb` against `djxl --color_space`. Conformance cases are also
  checked against their `test.json` tolerances where a `reference_image.npy` exists.
- Golden: unchanged results for the existing 1542 cases at 1 and 16 threads, plus the new cases.
- Fuzzing: the layered corpus is added to the seeds of the `decode` target; a short PC run (5 min) before release;
  long runs belong to 0.8.16.
- Speed: still-image matrix shows no regression; one layered case is added to the speed harness.

## Done when

- Every layered/cropped/blended still image from the corpus decodes and matches djxl as above; golden unchanged.
- `JxlReferenceFrames` accepts slots after the colour transform; `JxlPatches` and frame blending share `JxlBlending`.
- Working memory of layered images is charged; cancellation and failure tests cover the blending stage.
- README "Support" lists layers (flattened); "Not supported yet" no longer lists layers; release notes written.
- Release build, tests, pack and `scripts/verify-package-consumer.sh` pass.

## Results (2026-11-02)

- Code: `Rendering/JxlBlending` (per-pixel `PerformBlending` moved from `JxlPatches`, `BlendFrame`, `NeedsBlending`),
  `JxlReferenceFrames` with slots after the colour transform (`GetBackground`, `RetainedBytes`), the session loop
  above, `Color/JxlCanvasToSrgb`, `JxlWorkBudget.Used`/`Rewind`. The support policy no longer rejects layers, crops
  or blending, and accepts a skip-progressive last frame (libjxl reads `is_last` for it too).
- Corpus: ten `layers-*.jxl` from `jxl_from_tree` (every mode, crop, negative, outside and larger frames, three
  layers, 16-bit, XYB); the other corpus files regenerate byte for byte. Lossless layers match djxl's hash, XYB
  within the tolerance.
- Conformance: `blendmodes`, `mul_no_extra_channels` and `sunset_logo` identical to djxl at 8 bits; at 16 bits
  `layers-16bit` is identical and the alpha blends of `blendmodes`/`sunset_logo` differ by at most 1/65535 in a few
  thousand pixels (float rounding). `patches` differs from djxl's PNG only because djxl writes another colour space;
  it is within 1 of the conformance `ref.png`.
- ToSrgb: the canvas conversion matches djxl's direct sRGB rendering of `lossy-p3` and `icc-lossy-gray` within the
  normal tolerance; through the RGB ICC profile every sample is within 1 but 17 of 12288 differ (the normal limit is
  0.1 %), because the samples pass the profile's sampled tone curves twice.
- Tests 593 (547 + 46). Golden against 0.8.9: the 1542 results identical, 94 new lines for the layers files,
  identical at 1 and 16 threads. Pack and the package consumer (JIT, Native AOT) pass.
- Fuzzing on the PC, seed 21, 5 min each: `decode` 1.38 M inputs and `cancel-decode` 347 k, no finding;
  `diff-decode` 16 k inputs, no mismatch. Its two `accept` inputs are not from blending: a 1024² image with 64 extra
  channels exceeds the fuzzers' `MaxPixels` (2^22) working budget, whose 0.8.9 message `IsLimit` did not recognise
  (fixed in the harness); and a `jxlc` box declaring 0xFFFFFFFF bytes, which djxl reads to the end of the file and
  this library, like 0.8.9, rejects as truncated (left for 0.8.16).
- Not done: the speed matrix was not rerun; the still-image path is the 0.8.9 code (one `NeedsBlending` call more).
  Alpha blending with layered VarDCT frames and slots other than 1 have no corpus file yet (jxl_from_tree cannot
  write them); the conformance files cover alpha blending of Modular layers.
