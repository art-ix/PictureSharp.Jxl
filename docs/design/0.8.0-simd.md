# SIMD implementation plan for 0.8.0

Status: implemented locally, 2026-10-29 (S0–S5 done, S6 measured; release preparation pending).
Baseline: PictureSharp.Jxl 0.7.10, commit `6cd7f9bb3c85e47c6204c825e230b85165141cc5`.
Results: [speed measurements](../benchmarks/speed.md#simd-080): VarDCT decode 2.8–3.8×, lossy encode 1.4× (e1/e3)
and 2.4–2.6× (e5/e7) on an AVX2/FMA CPU; Modular and JPEG reconstruction controls within ±1%. Output identical to
0.7.10 (1433 golden results). The plan below is kept as written.
After 0.8.0 (released 2026-10-29; follow-up released in 0.8.1): copy-free DCT leaves and recursion, encoder convolution,
EPF sharpness block errors and Y dequantization added (encode e7 −18%, e1/e3 −10–11%, decode −2–6% vs 0.8.0); AOT and
SSE4.1-only speed measured for the first time. Details and rejected candidates:
[after 0.8.0](../benchmarks/speed.md#simd-after-080-released-in-081).
User decisions: SIMD in 0.8.0, multithreading in 0.8.1, further performance work in
0.8.2–0.8.5, then fuzzing and resilience work in 0.8.6–0.9.0.

## Baseline and measured priorities

Twelve cases were profiled from a fresh Release build of 0.7.10 on 2026-10-29:
Intel Core i5-12500H, Linux x64, SDK 10.0.401, runtime 10.0.12, CPU 0 affinity,
`DOTNET_TieredCompilation=0`, single-threaded codec. Collection used dotnet-trace
10.0.750501 with `dotnet-sampled-thread-time,dotnet-common`, exported to Speedscope.
The structured [profile results](../measurements/simd-profile-0.7.10.json) record
case IDs, iteration counts, input hashes, trace hashes and exclusive/inclusive attribution.
Raw traces and private images remain under ignored `artifacts/`.

Percentages below are samples on the busiest thread, including cold execution,
warmup and repeated calls. They are prioritization evidence, not warm benchmark timings.
Inlining affects method attribution. Inclusive rows overlap: do not add an outer
function's share to the shares of its callees. In particular, EstimateEntropy includes DCT/IDCT.

| Case | Measured cost | Planning consequence |
| --- | --- | --- |
| Photo 1 MP VarDCT decode, 8-bit | ScaledIdct 24.0% inclusive; EPF 18.6%; colour Apply 14.1%; dequantization 7.7%; Gaborish 4.8% | Shared transforms first, then colour and restoration |
| Photo 1 MP VarDCT decode, 16-bit output | ScaledIdct 24.6%; EPF 19.0%; colour Apply 15.6%; WriteWideRow 5.3% | Same main kernels benefit both depths |

| Photo lossy encode, e7, 8/16-bit | EstimateEntropy 63.9/63.5% inclusive, 14.8/15.7% exclusive; CfL Derivatives 11.1/11.9% exclusive | Optimize shared transforms before rewriting entropy estimation |

The twelve cases cover 8/16-bit photo encode/decode, lossy screen encode/decode,
low-effort photo encoding and 12 MP decoding. They are not a complete codec benchmark:
alpha, grayscale, ICC, JPEG reconstruction and all efforts still belong in correctness
and regression validation. After the first shared optimizations, collect a new profile
before selecting additional kernels. Historical 0.7.8 profiles are not the current baseline.

## Files and implementation boundaries

Follow the core's sibling-file and `partial` class organization. The exact suffix is
**`.Simd.cs`**, matching `JpegIdct.Simd.cs`, `YuvToRgb.Simd.cs`,
`HdrColorMatrix.Simd.cs` and `DeterministicMath.Simd.cs` in PictureSharp.
These are organizational examples; do not copy core internals or depend on them.

- Keep scalar implementations and orchestration in existing `.cs` files.
- Put vector kernels, their hardware dispatch helpers and vector constants in sibling
  `.Simd.cs` files on the same internal partial type. A scalar caller invokes the helper
  once per row/block; the helper returns the processed count or declines the operation.
- Put both AVX2 and SSE4.1 implementations in the owning `.Simd.cs` file, with explicit
  method names such as `...Avx2` and `...Sse41`. Avoid a global collection of unrelated kernels.
- Keep small tails scalar and dispatch outside pixel/coefficient loops. Do not allocate
  to dispatch or convert an entire image to a new layout just to feed SIMD.
- Retain existing cancellation boundaries, scoped pooled ownership and validated logical
  span lengths. ArrayPool capacity is not permission to read past the logical end.
- Use the BCL and public PictureSharp SPI only. No unsafe code, native dependencies,
  reflection, InternalsVisibleTo or public SIMD option. Library remains single-threaded in 0.8.0.

## CPU paths and numerical contract

The requested x86 backends are **AVX2 (256-bit)** and **SSE4.1 (128-bit)**, plus scalar.
SSE4.1 provides useful explicit rounding and unsigned packing operations for pixel output;
SSE4.2 is not required by this plan. See the [.NET SSE4.1 API](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.intrinsics.x86.sse41?view=net-10.0).
FMA is a separately detected capability, exposed by the [.NET Fma API](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.intrinsics.x86.fma?view=net-10.0).

| Kernel requirement | Dispatch preference | Fallback |
| --- | --- | --- |
| Integer or non-fused floating-point operations | AVX2, then SSE4.1 | Scalar |
| Explicit fused arithmetic used by the scalar kernel | AVX2 + FMA; an independently measured 128-bit FMA variant may also be used | Scalar kernel when exact fused SIMD is unavailable |
| Unsupported CPU, short input or unsupported layout | No vector call | Scalar |

A 128-bit FMA variant is not a pure SSE4.1 path: name and test that distinction.
SSE4.1 without AVX/FMA must actually accelerate eligible non-fused kernels, especially
output conversion; it must never execute AVX/FMA accidentally. FMA-heavy DCT, colour
and filter paths may remain scalar on those CPUs. Do not emulate each fused operation
lane-by-lane unless a measured complete operation still benefits. On other architectures,
retain scalar functionality; ARM64 vector implementation is outside this x86 SIMD scope.
Do not describe this x64 profile as ARM64 verification.

The result contract is the 0.7.10 scalar implementation, including its explicit
`MathF.FusedMultiplyAdd` calls. Preserve fused operations where present and separate
multiply/add where present. Preserve reduction order, intermediate float/double precision,
rounding mode, clamp semantics, signed zero and relevant exceptional-value behavior.
Do not introduce approximate reciprocal/sqrt/cbrt or new transfer-function approximations.
The core's deterministic math approximations are not replacements for JXL's formulas.

Prefer lanes representing independent pixels, columns or coefficients. Horizontal
float reductions in CfL, entropy estimation, filter sums and transform dot products
must not reorder accumulation. If vector arithmetic prepares contributions, consume them
in the original order; reject the candidate if that overhead removes the gain.

## Implementation sequence

### S0 — freeze baseline and establish differential tests

1. Preserve the 0.7.10 package, speed binary and golden output before modifying code.
   The existing 1283-result golden set matched 0.7.9 at release preparation; 0.7.10 is
   now the explicit SIMD comparison baseline. Do not regenerate expected values from SIMD.
2. Add focused scalar-versus-vector tests in the existing source-linked Codestream test
   arrangement. Keep a directly callable scalar reference and direct backend entry points
   for supported hardware; retain integration tests against the actual public library.
3. Test dispatch selection for AVX2/FMA, AVX2 without FMA, SSE4.1 without AVX/FMA and scalar.
   Execute only supported backends. Log detected capabilities so a skipped path cannot be
   mistaken for a passing SIMD test.
4. For process-level fallback checks, constrain runtime capabilities and verify reported
   support. Such switches can also change the core's code paths: use same-process JXL
   kernel comparisons for isolated evidence, not a whole-process scalar switch as a claim
   of JXL-only speedup. Keep all test controls outside the public API.
5. Inspect generated code on representative kernels to confirm intended vector instructions
   and absence of accidental fused arithmetic, heap allocation or scalarized hot loops.

Exit: scalar reference frozen; supported backend selection and edge-case comparison work.

### S1 — shared DCT/IDCT

File: `Codestream/VarDct/JxlDct.Simd.cs`; make `JxlDct` partial.

- Vectorize adjacent columns in `DctColumns`/`IdctColumns`: 2/4/8-point leaves, then the
  recursive row arithmetic for larger transforms. Each lane follows the original scalar
  butterfly and explicit FMA operations.
- Preserve transposition, scaling and scratch layout. Start with contiguous columns;
  measure gather/transposition separately rather than expanding the change immediately.
- Cover every supported transform dimension and rectangular shape; retain scalar handlers
  for special transforms until a separate candidate is verified and measured.
- Measure VarDCT photo/screen decode and e3/e7 encode at both depths. Because these functions
  are shared, run both decode and encode golden cases after each accepted change.

Exit: bitwise intermediate equality, unchanged encoded bytes/pixels and measured end-to-end win.

### S2 — output colour conversion

Files: `Codestream/Color/JxlColorOutput.Simd.cs` and, only for shared vector math,
`Codestream/Numerics/JxlFastMath.Simd.cs`.

- Begin with the common XYB-to-linear-to-sRGB row path in `Apply`, then YCbCr-to-RGB.
- Port the existing matrix order, bias/cube operations, rational polynomial, square root,
  threshold comparisons and sign restoration lane by lane. Keep explicit FMA exact.
- Handle the sRGB threshold and both signs explicitly. Keep ICC curves and less common
  transfers scalar until individually tested; the scalar tail uses the identical formula.
- Validate default decoding and ToSrgb, 8/16-bit output, gray/alpha and existing ICC corpus.

Exit: exact float/sample results and benefit on 1 MP and 12 MP decoding without a new image buffer.

### S3 — restoration filters

Files: `Codestream/Rendering/JxlRenderPipeline.Simd.cs`; encoder-side
`Codestream/Encoding/Lossy/JxlGaborish.Simd.cs` and `JxlConvolution.Simd.cs` only where justified.

- Start with Gaborish, then EPF2, EPF1 and EPF0, keeping each stage independently reviewable.
- Vectorize adjacent output pixels; accumulate each pixel's neighbors in scalar order.
- Preserve mirrored borders, block-specific sigma, border multipliers, skip thresholds
  and delayed-row commit timing. Split runs at 8-pixel sigma-block boundaries.
- Do not overwrite source rows still needed by the current or following vector block.
- Recheck encoder reconstruction/EPF sharpness search: shared filter changes can affect
  encoded bytes even when a decoder-only comparison appears correct.

Exit: exact borders/interiors for tiny and odd dimensions, all EPF stages, and photo/screen gain.

### S4 — dequantization and pixel output, including the SSE4.1 path

Files: `Codestream/VarDct/JxlVarDctFrame.Simd.cs`, `Integration/JxlPixelWriter.Simd.cs`;
`Codestream/Color/JxlDither.Simd.cs` only if reusable vector dither math is needed.

- Vectorize independent coefficient dequantization/CfL application without changing the
  coefficient order, integer overflow semantics, channel subsampling or explicit FMA.
- Implement non-fused SSE4.1 and AVX2 pixel kernels for float-to-Rgba64 and eligible
  Rgba32 output. Preserve gray/RGB and opaque/alpha specialization from 0.7.10.
- Preserve 8-bit dither positions, 32-column wrap, channel phase and nearest-even rounding.
  Preserve the current 16-bit clamp/round arithmetic exactly; do not reuse the 8-bit rule.
- Include integer Modular output only if measured: its current writer is approximately
  1.4–1.5% exclusive in these photo cases. Keep normalization before rounding unchanged.
- Test alpha exactly, including transparent RGB, and exhaust all 65536 input values for
  relevant 16-bit conversion kernels.

Exit: demonstrable SSE4.1-only execution, exact pixels and no allocations proportional to image size.

### S5 — encoder-specific candidates after re-profiling

Candidate files, created only for retained implementations:
`JxlAcStrategySearch.Simd.cs`, `JxlChromaFromLumaSearch.Simd.cs`,
`JxlCoefficientQuantizer.Simd.cs` under `Codestream/Encoding/Lossy/`,
`Codestream/Color/JxlXybInput.Simd.cs`, and
`Codestream/Encoding/JxlModularTransformChooser.Simd.cs`.

- Re-profile e3 and e7 after S1–S4. Treat EstimateEntropy's exclusive work separately
  from transforms it calls. Vectorize per-coefficient arithmetic and integer counts;
  preserve entropy/loss reduction order and all strategy tie-breaking decisions.
- CfL: begin with slope/offset preparation; prototype vector derivative contributions
  only with ordered summation. Keep fast-path fused recurrences scalar unless exactness
  and benefit are demonstrated. Do not use a horizontal vector sum to change the result.
- Low effort: inspect XYB input and quantization independently. Retain the exact CORE-MATH
  cbrtf result and input-table semantics; do not substitute a faster cube-root approximation.
- Lossless: investigate RCT scoring/transforms on independent samples. Leave sequential
  tree lookup, weighted prediction and adaptive entropy state alone without a specific
  dependency-safe design and measurements.

Exit: retain only independently measured wins. Unprofitable or unfinished candidates move
into 0.8.2–0.8.5, with the profile and rejection reason recorded; they do not weaken correctness.

### S6 — 0.8.0 acceptance and release preparation

- Full Release tests, full 0.7.10 golden comparison, public API snapshot unchanged.
- Scalar/SSE4.1/AVX2 matrix, FMA available/unavailable, with actual executed paths recorded.
  Verify JIT and package consumer under full trimming and linux-x64 Native AOT.
- Cover 8/16-bit input/output, gray/RGB/alpha, ToSrgb/ICC, all supported transforms,
  metadata rewrite and JPEG transcoding, lossless and lossy efforts 1–9.
- Test widths around vector boundaries: 1, 2, 3, 4, 7, 8, 9, 15, 16, 17, 31, 32, 33,
  odd strides, nonzero offsets, exact-length spans and untouched sentinels around output.
  Include malformed/truncated inputs, cancellation and budget failures for changed paths.
- Use paired before/after runs on the same CPU and same runtime configuration, without
  tracing/builds running concurrently. Report warm median, allocations, GC and peak RSS
  separately for 1 MP/12 MP photos and screens, both depths; include tiny images.
- Keep a candidate with at least 2% improvement in its declared end-to-end target and no
  reproducible >1% regression in control paths. Investigate borderline results with repeated
  alternating runs; a faster microkernel alone is insufficient. Report SSE4.1 and AVX2
  separately; hardware-masked runs on a modern CPU are not old-CPU performance measurements.
- Preserve the 0.7.10 memory reduction: no full-frame SIMD scratch or per-block heap churn.
  Report any extra scratch explicitly. Do not promise an overall speedup before measurement.
- Update benchmarks, architecture, release notes and package metadata only after acceptance.
  Commit, push, tag and publication still require the corresponding user request.

The systematic fuzzing campaign starts in 0.8.6. Boundary and regression tests required
for safe SIMD changes remain part of 0.8.0.

## Roadmap after SIMD

| Version | Planned outcome |
| --- | --- |
| 0.8.1 | Parallel independent groups using the accepted SIMD kernels; deterministic merge order; thread-count API decision, cancellation and per-worker memory limits; identical output at 1/N threads |
| 0.8.2 | Re-profile combined SIMD/threading; optimize demonstrated scheduling, group-size and load-balance bottlenecks |
| 0.8.3 | Further measured encoder improvements, including deferred S5 candidates, with unchanged compression decisions |
| 0.8.4 | Further measured decoder/Modular and 8/16-bit improvements; any additional CPU backend requires its own hardware validation |
| 0.8.5 | Performance and memory consolidation; small-image overhead, concurrency scaling and final benchmark baseline for hardening |
| 0.8.6 | Mutation fuzzing of container, bitstream, entropy readers, dimensions and vector/tail boundaries; minimize failures into regression cases |
| 0.8.7 | Differential interoperability fuzzing against pinned cjxl/djxl; decode, encode, metadata and byte-exact JPEG reconstruction within supported scope |
| 0.8.8 | Resource and failure resilience: allocation/pixel/metadata budgets, overflow, cancellation, failed/non-seekable streams and pooled-buffer cleanup |
| 0.8.9 | Longer reproducible fuzz campaigns, parallel execution stress, scalar/SIMD/thread-count comparisons, corpus deduplication and regression triage |
| 0.9.0 | Close hardening findings; complete correctness/package/AOT matrix, publish coverage and limitations, prepare the stabilization release |

The 0.8.2–0.8.5 breakdown is a proposed allocation of improvement work; fresh profiles
may reorder candidates within that window. The user-approved milestone boundaries stay
fixed. Algorithm/quality changes that alter output require a separate decision and baseline.
