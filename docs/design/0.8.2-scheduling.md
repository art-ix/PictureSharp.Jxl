# Scheduling and encoder scratch for 0.8.2

Status: released in 0.8.2. Base: `df9f7a7` (`v0.8.1`).
This step preserves the frozen all-efforts output and the public API. It targets the remaining serial work in
JPEG reconstruction and lossless encoding, and the large per-worker allocations in lossy encoding.
Measurements and verification are recorded in [speed.md](../benchmarks/speed.md#scheduling-and-scratch-082).

## JPEG reconstruction

`JxlJpegWriter.Bits` accumulates bits in a 64-bit register and emits whole bytes to a buffer, including JPEG's
zero-byte stuffing after `0xff`. The previous implementation called the output stream for every completed byte
and visited every input bit separately. Padding and restart marker placement keep their original order.

Scans starting at DC with no successive-approximation refinement (`Ss = 0`, `Ah = 0`) can be encoded in independent
MCU chunks. For these scans EOB runs do not cross blocks; the only carried coefficient state is each component's
DC predictor. Chunk boundaries are whole restart intervals, or whole MCU rows when there are no restarts.
The number of chunks is bounded by four times the available workers and by the number of units in the scan.

Each chunk:

- starts with zero DC predictors at a restart, or the last DC coefficients immediately before its boundary;
- finds the prefix of reset and extra-zero-run positions already consumed by the sequential writer;
- encodes unstuffed bit strings, retaining the final partial byte of each restart segment;
- writes only its own result slot through `JxlParallel`.

The caller merges chunks in scan order, joins partial bytes, applies stuffing and original padding, and inserts
restart markers. Other progressive scans keep the sequential path. Buffers are per scan/chunk and owned by the
call; this introduces temporary encoded-data storage, not a new pixel budget or a strict temporary-memory limit.

Malformed input needs one extra ordering rule: padding is validated at merge time, while a worker can encounter
a coefficient error later in the scan. If chunk encoding throws `ImageFormatException`, the scan is replayed
sequentially before any chunk has been appended or padding consumed. This reports the same first error as degree 1,
including when missing padding precedes a bad coefficient in the same or a later chunk. Valid scans retain the
parallel path; cancellation is not caught by this fallback.

## Lossless encoding

### MA-tree learning

Property quantization runs independently per property. The learner then splits the largest outstanding nodes,
evaluating their candidate properties in parallel with private search scratch. It selects the best split in the
original property/bin order, keeping all tie-breaking and floating-point operations within each candidate intact.

Once outstanding nodes contain at most one worker's share of the sample count, independent subtrees run on workers,
largest first. Their partitions touch disjoint sample ranges; each subtree records its split decisions locally.
The caller replays those decisions in the original depth-first, left-before-right order, so node numbering and
the serialized tree remain identical. Regions do not nest. One subtree share per worker was retained after
measurement; more, smaller scheduling units were not assumed to be faster.

### RCT and palette

RCT candidates compute their costs independently and the caller selects in the original transform order.
The candidate arithmetic and acceptance threshold are unchanged.

Palette discovery collects colour sets in row bands. If any band exceeds the colour limit or contains a value
outside the supported 16-bit range, the palette is rejected as before. The merged set is sorted by the same luma
and key ordering. Index mapping also runs in bands; repeated colours reuse the previous lookup. Shared channel
storage and the output index plane exist before workers start. The 1024-colour acceptance boundary is covered by
images with exactly the limit and one additional colour in the last band.

## Lossy encoder scratch

The AC strategy search chooses transforms no larger than DCT64×64. AC search, chroma-from-luma search and coefficient
quantization now share that bound: 4096 coefficients instead of the decoder-wide DCT256×256 maximum of 65536.
The decoder's transform support is unchanged. Search and quantizer scratch are still private to each worker.
If a future encoder adds larger transforms, its shared bound must grow with them.

## Verification and measurement contract

- Full Release suite, including byte identity at degrees 1/2/3/7/64/-1, corrupt reconstruction mutations and the
  ordering of padding versus coefficient errors.
- All 1433 frozen golden results at degrees 1 and -1, covering pixels, encoded/transcoded bytes, metadata and
  malformed-input outcomes; no baseline regeneration.
- Native AVX2/FMA, SSE4.1-only and scalar differential tests; package consumer under JIT and trimmed linux-x64 AOT.
- Frozen 0.8.1 versus current builds at the same degree and CPU affinity, alternating A/B and B/A, without
  concurrent builds or profiling. Record warm times, allocations, GC and peak RSS, including 8/16-bit and 12 MP
  inputs. Recheck differences near the 1% regression threshold, especially lossless photo encoding after palette
  changes. `scripts/measure-paired.py` saves every process result and input/build hashes.

## Deferred or rejected work

Exploratory measurements rejected finer decode bands (2–4 per worker: 12 MP decode 4–6% slower), a histogram-pair
cost cache (no gain), and parallel zero counting (no gain; 1-thread run 1.4% slower). Skipping the core Image buffer
initialization would change `HasAlpha` and needs a separate core API. Streaming JPEG output through a fixed 4 KiB
buffer instead of per-chunk byte buffers was 3% slower at 16 threads without lower memory. None is included here.

A 1 MP VarDCT frame usually has only one LF group. Its DC modular entropy stream is sequential; additional
scheduling cannot subdivide that stream. Lossless effort tiers and other compression decisions are deferred to
0.8.3 under the separately agreed size/quality contract. This step keeps byte identity.
