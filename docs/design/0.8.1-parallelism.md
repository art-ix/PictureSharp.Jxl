# Deterministic group parallelism in 0.8.1

Status: released in 0.8.1, 2026-10-29. Base: commit 8f4d64b (0.8.0 plus the follow-up SIMD kernels).
Results: [speed measurements](../benchmarks/speed.md#group-parallelism-081): lossless decode 5–8×, VarDCT
decode 1.9–3.2×, lossy encode e7 3.1–4.6×, lossless encode 1.3–4× at 16 threads vs 1 thread; golden identical.
Output contract: every encoded byte, decoded pixel, metadata edit, transcoded JPEG and exception is identical at
1 and N threads and identical to the frozen all-efforts golden set (1433 results, SHA-256 92d936fd…e06).

## Public API (user decisions 3 and 7, 2026-10-29)

| Operation | Option | Default |
| --- | --- | --- |
| Decode, Identify, ReadMetadata | core `DecoderOptions.MaxDegreeOfParallelism` (PictureSharp 0.9.0) | -1 |
| Encode | `JxlEncoderOptions.MaxDegreeOfParallelism` | -1 |
| FromJpeg / ToJpeg | `JxlTranscoderOptions.MaxDegreeOfParallelism` | -1 |

The value is -1 (automatic: the thread pool decides, at most `Environment.ProcessorCount` useful workers) or ≥ 1;
other values throw `ArgumentOutOfRangeException` when set, as in the core (`Check.Parallelism`). 1 runs exactly the
previous single-threaded code on the calling thread. No JPEG XL decoder option is added: the core has one.
Metadata editing copies frames without decoding them and stays sequential.

## Execution model

`JxlParallel.For(count, degree, cancellationToken, body)` (Codestream/Numerics, BCL only) is the only parallel
primitive. With degree 1 or count ≤ 1 it is a plain loop. Otherwise it runs `Parallel.For` without passing the token
to `ParallelOptions` (no wrapped `OperationCanceledException`), and each index:

1. is skipped when an index below it has already failed;
2. checks the token, then runs the body;
3. on an exception records it if its index is the lowest failed so far.

After the join the lowest-index exception is rethrown unchanged with `ExceptionDispatchInfo`. Every index below
it has completed, so the exception is the one the sequential loop throws first: `ImageFormatException`,
`NotSupportedException`, `OperationCanceledException` and their messages are kept, never an `AggregateException`.
Cancellation is checked by the workers at the same per-row/per-block points as before plus once per index.
Regions never nest: a worker never starts another region, so the thread count is bounded by the degree.

## Determinism rules

- Work items are the units the format already makes independent: TOC sections (LF groups, pass groups), Modular
  streams, 64×64 encoder tiles, 256×256 groups, row bands of pointwise or stencil stages.
- A work item writes only its own disjoint rectangle of shared planes, or its own slot of a result array; results
  that are combined (token lists, tree samples, histograms, the AC strategy set, sums) are merged after the join
  in item order exactly as the sequential loop produced them. No floating-point value is accumulated across items
  in a different order.
- Stencil stages (Gaborish, EPF, encoder convolution) read only unfiltered input: each row band keeps its first
  and last `reach` output rows until every band has finished, then writes them back. A one-band run therefore
  equals the previous `DelayedRows` order, and every output pixel is a function of the unfiltered plane at any
  band count.
- Lazily created shared state is created before the region: full-image channel storage (`JxlChannel.Pixels`),
  tokens/coefficients owned by shared scopes. Lazily computed quantization matrices use a compare-exchange
  publication; competing computations produce identical arrays.
- Pseudo-random tree sampling uses a fixed xorshift32 sequence over all pixels in stream/channel/scan order. Each
  channel scanned in parallel starts at the state the sequential scan would have (jump-ahead by the pixel count
  through the GF(2) matrix of the generator) and records its samples in its own buffer; buffers are appended to
  the learner in channel order.

## Stages

| Stage | Parallel unit | Stays sequential |
| --- | --- | --- |
| Decode: LF groups (VarDCT DC, AC metadata, Modular LF) | LF group | LF global, `FinishLf` (DC smoothing), progress bookkeeping |
| Decode: pass groups + group rendering / JPEG coefficient recovery | group (all passes of a group) | HF global, coefficient orders/histograms |
| Decode: Modular groups | group | global tree and global stream, inverse transforms that span groups (squeeze, palette, RCT) |
| Rendering: Gaborish, EPF 0/1/2, colour output, upsampling, pixel writer | row band | patches, plane mirroring, expand-gray |
| Encode lossy: XYB input, adaptive quantization maps, inverse Gaborish | row band | patch search, global scale |
| Encode lossy: AC strategy search, chroma from luma | 64×64 tile (per-worker search scratch) | quant field adjustment, block context model |
| Encode lossy: quantization, AC tokenization, EPF sharpness search | 256×256 group | coefficient orders, histogram clustering, entropy code, section order |
| Encode lossless: tree sample scan with weighted errors, residual tokenization | channel / stream | palette/RCT choice, `FindSplit` tree learning, histograms, entropy coding order |
| JPEG transcoding: AC tokenization; reconstruction: coefficient recovery | group | JPEG parsing/writing, jbrd |

The global MA tree, histogram clustering, ANS/prefix codes and section order are computed exactly as before from the
merged inputs. TOC sizes are known before writing; output still goes directly to the caller's stream.

## Memory, ownership and budgets

- Per-worker scratch (DCT blocks, AC search and CfL buffers, quantizer blocks, delayed stencil rows, nonzero tables)
  is created by the worker and released by it in `finally`/`using`; it is bounded by degree × one group or tile.
- `JxlBufferScope.Own`/`Lease` are synchronized so a call-level scope may receive rentals from workers; it is still
  disposed once, on the owning thread, after the region has joined (including after a failure).
- Budget charges (`ReservePixels`, `ReserveMetadata`, transcoder `MaxPixels`/`MaxMetadataBytes`) stay on the calling
  thread, before any region starts; workers never reserve, so nothing is charged twice and a budget failure throws
  before workers exist. `ReservePixels` still limits the output image; temporary per-worker memory is documented,
  not charged, as for 0.7.10 temporary storage.
- Retained results are as in 0.8.0 (all group coefficients/tokens of a frame); concurrent work adds at most
  degree − 1 groups of in-flight decoder coefficients.

## Verification

- Golden: all-efforts set at `MaxDegreeOfParallelism` 1 and -1 (16 logical CPUs), both identical to the frozen file.
- Tests: 1 vs N determinism (decode/srgb/16-bit/alpha/Modular/VarDCT/patches/JPEG reconstruction/encode at efforts
  1–9/transcoding) including N > groups; cancellation before and during regions; corrupt sections in several groups
  (lowest-index exception wins, same type/message as 1 thread); budget failures at N threads; option validation;
  public API snapshot.
- `scripts/verify-simd.sh` (native/SSE4.1/scalar) and package consumer under JIT and Native AOT.
- Speed: paired runs, tiered compilation off, no concurrent load; 1 thread pinned to one CPU, N threads pinned to the
  recorded CPU list; 0.8.0 package vs 1 vs N; cjxl/djxl 0.12.0 with `--num_threads`.
